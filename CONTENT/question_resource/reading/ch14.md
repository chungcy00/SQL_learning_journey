## q0186 · 生成不越过截止日的巡检计划
题型：独立编写　难度：简单　知识点：kp14-02

仓库每隔若干天巡检一次，实际间隔和截止日由配置表决定。日编号是相对起点的整数，不是日期字符串。

从 schedule_bounds 的唯一一行读取起始日编号、正整数间隔天数和截止日编号。使用递归 CTE 生成所有不超过截止日的计划编号（包含起点），不得写死参数；起点不晚于截止日。输出 n，按 n 升序。
输出列名称及顺序：n。按 n 升序。

公开数据：schedule_bounds

| start_day | step_days | max_day |
|---:|---:|---:|
|0|3|10|

提示：
1. 找到起点、步长和截止日三个参数；递归每轮需要继续携带哪些字段？
2. 输出的最后一项不一定等于截止日；检查生成下一项的条件。
3. 递归成员生成 n+step_days，只有下一项不超过 max_day 时才能继续。

<details><summary>参考答案与解析（先自行完成）</summary>

**参考解（MySQL）**
```sql
WITH RECURSIVE schedule(n,step_days,max_day) AS (SELECT start_day,step_days,max_day FROM schedule_bounds UNION ALL SELECT n+step_days,step_days,max_day FROM schedule WHERE n+step_days<=max_day) SELECT n FROM schedule ORDER BY n;
```

**等价解**
```sql
WITH RECURSIVE schedule(n,step_days,max_day) AS (SELECT start_day,step_days,max_day FROM schedule_bounds UNION ALL SELECT n+step_days,step_days,max_day FROM schedule WHERE n<=max_day-step_days) SELECT n FROM schedule ORDER BY n;
```

公开结果：n = 0、3、6、9。

递归起点与步长均从参数表读取。递归前检查下一编号是否超过截止日，而非只检查当前编号。公开参数为起点0、步长3、截止10，输出0、3、6、9；如果只检查当前编号小于10，将错误生成12。等价解将下一编号的条件移项到右边，适用于本题的小整数参数。

常见错误：仅检查当前编号是否小于截止日，会让下一编号跨越边界。

## kp17-01 CREATE TABLE 与约束

### 概念
建表定义字段类型、主键、非空、唯一、检查约束及外键。约束在写入时保障有效性。

### 语法
```sql
CREATE TABLE t (id INT PRIMARY KEY, qty INT NOT NULL CHECK(qty>=0));
```

### 参数说明
- `PRIMARY KEY`：主键
- `CHECK`：检查规则

### 原始数据

本例使用常量或在隔离库创建演示表，不依赖现有数据。

初始化及操作：
```sql
CREATE TABLE demo_stock(id INT PRIMARY KEY NOT NULL,qty INT NOT NULL CHECK(qty>=0)); INSERT INTO demo_stock VALUES(1,10),(2,20);
```

### MySQL 示例
```sql
SELECT id,qty FROM demo_stock ORDER BY id;
```

### 执行过程
1. 在隔离库建表
2. 写入两条库存
3. 查询验证

### 执行结果
| id | qty |
| --- | --- |
| 1 | 10 |
| 2 | 20 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
为实验室建立库存表

### 用法辨析
NOT NULL 不代表非负；CHECK 不替代 NOT NULL。

### 常见错误
错误：qty INT CHECK(qty>=0) 期待禁止NULL

修正：qty INT NOT NULL CHECK(qty>=0)

### 注意事项
MySQL 与 SQLite 的类型、主键和约束行为不同；只验证本例子集。

## kp17-02 INSERT、UPDATE、DELETE

### 概念
INSERT 新增行，UPDATE 修改匹配行，DELETE 删除匹配行；写操作先确定 WHERE 匹配范围。

### 语法
```sql
INSERT INTO t(cols) VALUES(vals); UPDATE t SET col=val WHERE p; DELETE FROM t WHERE p;
```

### 参数说明
- `cols,vals`：列及对应值
- `p`：目标条件

### 原始数据

本例使用常量或在隔离库创建演示表，不依赖现有数据。

初始化及操作：
```sql
CREATE TABLE demo_stock(id INT PRIMARY KEY,qty INT); INSERT INTO demo_stock VALUES(1,10),(2,20),(3,30); UPDATE demo_stock SET qty=25 WHERE id=2; DELETE FROM demo_stock WHERE id=3;
```

### MySQL 示例
```sql
SELECT id,qty FROM demo_stock ORDER BY id;
```

### 执行过程
1. 插入三行
2. 修改编号2库存为25
3. 删除编号3
4. 查询剩余行

### 执行结果
| id | qty |
| --- | --- |
| 1 | 10 |
| 2 | 25 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
维护个人实验室库存记录

### 用法辨析
DELETE 删除行；DROP 删除表结构；UPDATE 无 WHERE 会修改全部行。

### 常见错误
错误：UPDATE demo_stock SET qty=25

修正：UPDATE demo_stock SET qty=25 WHERE id=2

### 注意事项
只在隔离副本运行，不改内置题库。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp17-03 ALTER TABLE 与 DROP TABLE

### 概念
ALTER 修改表结构；DROP 删除表。某些结构修改需重建数据表或转换引擎语法。

### 语法
```sql
ALTER TABLE t ADD COLUMN label VARCHAR(80); DROP TABLE t;
```

### 参数说明
- `ADD COLUMN`：增加字段
- `DROP TABLE`：删除整个表

### 原始数据

本例使用常量或在隔离库创建演示表，不依赖现有数据。

初始化及操作：
```sql
CREATE TABLE demo_stock(id INT PRIMARY KEY); INSERT INTO demo_stock VALUES(1); ALTER TABLE demo_stock ADD COLUMN label VARCHAR(80); CREATE TABLE disposable(id INT); DROP TABLE disposable;
```

### MySQL 示例
```sql
SELECT id,label FROM demo_stock ORDER BY id;
```

### 执行过程
1. 新建演示表
2. 增加可空字段
3. 检查旧行字段为空
4. 删除另一个临时表

### 执行结果
| id | label |
| --- | --- |
| 1 | NULL |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
为个人数据集补充字段

### 用法辨析
DELETE 不删除结构；DROP 不保留数据。

### 常见错误
错误：直接 DROP 内置库表

修正：先复制到个人库并备份

### 注意事项
MySQL ALTER 的 MODIFY/CHANGE 等形式不等同 SQLite；DDL 常触发隐式提交。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp17-04 事务、COMMIT 与 ROLLBACK

### 概念
事务将一组写操作作为逻辑单位；提交使修改持久化，回滚撤销未提交的事务修改。

### 语法
```sql
START TRANSACTION; UPDATE ...; COMMIT; 或 ROLLBACK;
```

### 参数说明
- `COMMIT`：确认事务
- `ROLLBACK`：撤销事务

### 原始数据

本例使用常量或在隔离库创建演示表，不依赖现有数据。

初始化及操作：
```sql
CREATE TABLE demo_stock(id INT PRIMARY KEY,qty INT); INSERT INTO demo_stock VALUES(1,10); START TRANSACTION; UPDATE demo_stock SET qty=99; ROLLBACK; START TRANSACTION; UPDATE demo_stock SET qty=12; COMMIT;
```

### MySQL 示例
```sql
SELECT id,qty FROM demo_stock ORDER BY id;
```

### 执行过程
1. 初始库存10
2. 事务内改99后回滚
3. 新事务改12后提交
4. 查询结果12

### 执行结果
| id | qty |
| --- | --- |
| 1 | 12 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
验证库存变更是否正确提交

### 用法辨析
MySQL START TRANSACTION 对应 SQLite BEGIN；MySQL 多种 DDL 隐式提交。

### 常见错误
错误：认为 DROP TABLE 在 MySQL 中总能回滚

修正：将 DDL 与 DML 事务分离，并使用备份

### 注意事项
演示只涉及 DML；MySQL InnoDB 事务与 SQLite 锁模型不同。

### 兼容性
转换执行。需要明确转换或原生环境验证。

关联闪卡：fc0129、fc0135

## kp17-05 主外键、UNIQUE 与数据完整性

### 概念
主键保证唯一且非空；UNIQUE 约束避免业务键重复；外键要求非空引用对应父记录。

### 语法
```sql
CREATE TABLE child(id INT PRIMARY KEY, parent_id INT, FOREIGN KEY(parent_id) REFERENCES parent(id));
```

### 参数说明
- `parent_id`：引用父记录的字段
- `UNIQUE`：唯一组合约束

### 原始数据

本例使用常量或在隔离库创建演示表，不依赖现有数据。

初始化及操作：
```sql
CREATE TABLE demo_parent(id INT PRIMARY KEY NOT NULL, code VARCHAR(20) NOT NULL UNIQUE); CREATE TABLE demo_child(id INT PRIMARY KEY NOT NULL,parent_id INT,FOREIGN KEY(parent_id) REFERENCES demo_parent(id)); INSERT INTO demo_parent VALUES(1,'A'),(2,'B'); INSERT INTO demo_child VALUES(1,1),(2,1);
```

### MySQL 示例
```sql
SELECT p.id,COUNT(c.id) AS children FROM demo_parent p LEFT JOIN demo_child c ON p.id=c.parent_id GROUP BY p.id ORDER BY p.id;
```

### 执行过程
1. 建立父表及子表约束
2. 写入两个父记录及两个有效子记录
3. 验证映射

### 执行结果
| id | children |
| --- | --- |
| 1 | 2 |
| 2 | 0 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
设计客户与订单等关系并保护引用完整性

### 用法辨析
两个子行可以引用同一父行；不应把外键一律设为唯一。

### 常见错误
错误：插入没有对应父编号的子记录

修正：先创建有效父记录或修正引用

### 注意事项
本地连接务必开启外键检查；SQLite 的 PRAGMA foreign_keys 不属于 MySQL。

直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

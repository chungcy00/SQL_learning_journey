## kp09-01 CASE WHEN 分类

### 概念
按顺序检查 WHEN，返回首个为真的分支；ELSE 提供默认结果。

### 语法
```sql
CASE WHEN condition THEN value ELSE other END
```

### 参数说明
- `condition`：分类条件
- `value`：返回值

### 原始数据

**products**

| product_id | product_name | category | price | stock |
| --- | --- | --- | --- | --- |
| 1 | Mask | 护肤品 | 15 | 150 |
| 2 | Serum | 护肤品 | 89 | 40 |
| 3 | Cleanser | 护肤品 | 35 | 200 |
| 4 | Cream | 化妆品 | 65 | 180 |
| 5 | Sunscreen | 化妆品 | 45 | 80 |
| 6 | Soap_1 | 日用品 | 15 | 0 |

### MySQL 示例
```sql
SELECT product_id, CASE WHEN stock=0 THEN '缺货' WHEN stock<50 THEN '低库存' ELSE '正常' END AS stock_level FROM products ORDER BY product_id;
```

### 执行过程
1. 先判零库存
2. 再判小于50
3. 其余归正常

### 执行结果
| product_id | stock_level |
| --- | --- |
| 1 | 正常 |
| 2 | 低库存 |
| 3 | 正常 |
| 4 | 正常 |
| 5 | 正常 |
| 6 | 缺货 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
生成库存状态标签

### 用法辨析
CASE 是表达式而非过滤语句。

### 常见错误
错误：先 WHEN stock<50 再 WHEN stock=0

修正：把更具体的零库存条件放前面

### 注意事项
省略 ELSE 时未匹配返回 NULL。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp09-02 IF 与条件聚合

### 概念
MySQL IF(condition,a,b) 可用于简单二选一；CASE 更通用。SUM(CASE...) 可在同一查询统计不同子集。

### 语法
```sql
SUM(CASE WHEN p THEN 1 ELSE 0 END)
```

### 参数说明
- `p`：目标条件

### 原始数据

**products**

| product_id | product_name | category | price | stock |
| --- | --- | --- | --- | --- |
| 1 | Mask | 护肤品 | 15 | 150 |
| 2 | Serum | 护肤品 | 89 | 40 |
| 3 | Cleanser | 护肤品 | 35 | 200 |
| 4 | Cream | 化妆品 | 65 | 180 |
| 5 | Sunscreen | 化妆品 | 45 | 80 |
| 6 | Soap_1 | 日用品 | 15 | 0 |

### MySQL 示例
```sql
SELECT SUM(CASE WHEN stock<50 THEN 1 ELSE 0 END) AS low_count, SUM(CASE WHEN stock>=50 THEN 1 ELSE 0 END) AS normal_count FROM products;
```

### 执行过程
1. 每行映射为0或1
2. 分别求和

### 执行结果
| low_count | normal_count |
| --- | --- |
| 2 | 4 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
同时统计不同库存区间

### 用法辨析
COUNT(CASE WHEN p THEN 1 ELSE 0 END) 会计入所有行。

### 常见错误
错误：COUNT(CASE WHEN stock<50 THEN 1 ELSE 0 END)

修正：SUM(CASE WHEN stock<50 THEN 1 ELSE 0 END)

### 注意事项
MySQL IF 可换写 CASE；NULL 条件走 ELSE。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp09-03 NULLIF 与安全除法

### 概念
NULLIF(a,b) 相等时返回 NULL，否则返回 a；用来避免零作分母。

### 语法
```sql
numerator / NULLIF(denominator,0)
```

### 参数说明
- `denominator`：可能为零的分母

### 原始数据

**products**

| product_id | product_name | category | price | stock |
| --- | --- | --- | --- | --- |
| 1 | Mask | 护肤品 | 15 | 150 |
| 2 | Serum | 护肤品 | 89 | 40 |
| 3 | Cleanser | 护肤品 | 35 | 200 |
| 4 | Cream | 化妆品 | 65 | 180 |
| 5 | Sunscreen | 化妆品 | 45 | 80 |
| 6 | Soap_1 | 日用品 | 15 | 0 |

### MySQL 示例
```sql
SELECT product_id, ROUND(1.0*price/NULLIF(stock,0),2) AS ratio FROM products ORDER BY product_id;
```

### 执行过程
1. 分母为0转NULL
2. 其他记录进行小数除法
3. 保留两位

### 执行结果
| product_id | ratio |
| --- | --- |
| 1 | 0.1 |
| 2 | 2.23 |
| 3 | 0.17 |
| 4 | 0.36 |
| 5 | 0.56 |
| 6 | NULL |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
构建有定义的比率指标

### 用法辨析
IFNULL 把缺失变成默认值，NULLIF 把特定值变为缺失。

### 常见错误
错误：price/stock 不处理零库存

修正：price/NULLIF(stock,0)

### 注意事项
示例比率只演示语法，不是业务库存指标；SQLite 整数除法需提升类型。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp09-04 IF 二选一

### 概念
MySQL IF(expr,a,b) 在 expr 为真时返回 a，否则返回 b；未知条件也走否定分支。

### 语法
```sql
IF(condition,true_value,false_value)
```

### 参数说明
- `condition`：判断条件
- `true_value`：成立时的值
- `false_value`：不成立或未知时的值

### 原始数据

**nullable_values**

| id | value | note |
| --- | --- | --- |
| 1 | NULL | NULL |
| 2 | 0 | （空字符串） |
| 3 | 10 | ok |
| 4 | 10 | ok |

### MySQL 示例
```sql
SELECT id,IF(value>0,'正值','非正值或缺失') AS label FROM nullable_values ORDER BY id;
```

### 执行过程
1. 对每行判断 value>0
2. 空值条件未知
3. 零值和空值均走第二分支

### 执行结果
| id | label |
| --- | --- |
| 1 | 非正值或缺失 |
| 2 | 非正值或缺失 |
| 3 | 正值 |
| 4 | 正值 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
生成简单二分类标签

### 用法辨析
IF 适用于二选一；CASE 可处理多分支，并具备更广泛的可移植性。

### 常见错误
错误：IF(value>0,'正值','零值') 把NULL误归为零

修正：使用 CASE WHEN value IS NULL THEN ... 明确缺失类别

### 注意事项
本例采用文本输出，避免两分支混合类型导致引擎推断差异。

### 兼容性
转换执行。需要明确转换或原生环境验证。

本地转换示例：
```sql
SELECT id,CASE WHEN value>0 THEN '正值' ELSE '非正值或缺失' END AS label FROM nullable_values ORDER BY id;
```

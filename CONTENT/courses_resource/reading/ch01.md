## kp01-01 数据库、表、行与列

### 概念
数据库组织相关数据；表描述一种实体或事件，行是一次记录，列是属性。订单表的一行表示一笔订单，不一定表示一个客户。

### 语法
```sql
SELECT column FROM table;
```

### 参数说明
- `column`：字段名
- `table`：数据表名

### 原始数据

**orders**

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### MySQL 示例
```sql
SELECT id, category, sales FROM orders ORDER BY id;
```

### 执行过程
1. 定位订单表
2. 逐行提取三个字段
3. 按编号展示

### 执行结果
| id | category | sales |
| --- | --- | --- |
| 1 | 护肤品 | 800 |
| 2 | 化妆品 | 400 |
| 3 | 护肤品 | 600 |
| 4 | 化妆品 | 300 |
| 5 | 日用品 | 1500 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
识别订单数据的粒度

### 用法辨析
数据库是容器，表是关系结构；表格行序本身无保证。

### 常见错误
错误：把客户数等同订单行数。

修正：检查客户编号是否重复，客户数用去重计数。

### 注意事项
先判断一行代表什么，否则连接与汇总容易重复。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp01-02 数据类型与数据字典

### 概念
整数表示数量或编号；DECIMAL 用于精确十进制金额；VARCHAR 用于文本；DATE 表示日期。字段还需说明可空、单位及约束。

### 语法
```sql
CREATE TABLE t (id INT, amount DECIMAL(12,2), label VARCHAR(80), day DATE);
```

### 参数说明
- `DECIMAL(12,2)`：总精度12，小数2位
- `DATE`：日期，不含时刻

### 原始数据

**products**

| product_id | product_name | category | price | stock |
| --- | --- | --- | --- | --- |
| 1 | Mask | 护肤品 | 15 | 150 |
| 2 | Serum | 护肤品 | 89 | 40 |
| 3 | Cleanser | 护肤品 | 35 | 200 |
| 4 | Cream | 化妆品 | 65 | 180 |
| 5 | Sunscreen | 化妆品 | 45 | 80 |
| 6 | Soap_1 | 日用品 | 15 | 0 |

### MySQL 示例
```sql
SELECT product_id, price, stock FROM products ORDER BY product_id;
```

### 执行过程
1. 读取编号、单价、库存
2. 识别各字段业务含义

### 执行结果
| product_id | price | stock |
| --- | --- | --- |
| 1 | 15 | 150 |
| 2 | 89 | 40 |
| 3 | 35 | 200 |
| 4 | 65 | 180 |
| 5 | 45 | 80 |
| 6 | 15 | 0 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
判断字段应采用何种类型

### 用法辨析
数字型编号不等于可求和指标；文本日期不等于日期类型。

### 常见错误
错误：用浮点数精确表示货币。

修正：金额使用 DECIMAL，离线明确舍入或整数分。

### 注意事项
课例金额为整数；SQLite 类型亲和性不同于 MySQL 严格类型。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp01-03 主键、外键和一对多

### 概念
主键唯一且非空；外键约束引用有效父记录，可以允许空值。一名客户可以有多个订单。

### 语法
```sql
PRIMARY KEY (id); FOREIGN KEY (customer_id) REFERENCES customers(customer_id);
```

### 参数说明
- `PRIMARY KEY`：唯一标识
- `FOREIGN KEY`：引用关系

### 原始数据

**orders**

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

**customers**

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

### MySQL 示例
```sql
SELECT c.customer_id, COUNT(o.id) AS order_count FROM customers c LEFT JOIN orders o ON c.customer_id=o.customer_id GROUP BY c.customer_id ORDER BY c.customer_id;
```

### 执行过程
1. 以客户为起点
2. 匹配订单
3. 统计非空订单编号

### 执行结果
| customer_id | order_count |
| --- | --- |
| 1 | 2 |
| 2 | 1 |
| 3 | 1 |
| 4 | 0 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
读懂客户与订单关系

### 用法辨析
主键保证唯一；外键不保证唯一。

### 常见错误
错误：把订单表 customer_id 设置唯一，阻止重复购买。

修正：订单编号为主键，客户编号为外键。

### 注意事项
演示表用于学习；生产约束见后续建表课程。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp01-04 NULL 与缺失记录

### 概念
NULL 表示未知或缺失，并非零或空文本；外键为空可以表示访客订单。

### 语法
```sql
column IS NULL
```

### 参数说明
- `column`：待检测字段

### 原始数据

**nullable_values**

| id | value | note |
| --- | --- | --- |
| 1 | NULL | NULL |
| 2 | 0 | （空字符串） |
| 3 | 10 | ok |
| 4 | 10 | ok |

### MySQL 示例
```sql
SELECT id, value, note FROM nullable_values WHERE value IS NULL ORDER BY id;
```

### 执行过程
1. 检查每一行
2. 保留值缺失的记录

### 执行结果
| id | value | note |
| --- | --- | --- |
| 1 | NULL | NULL |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
识别缺失数据

### 用法辨析
NULL、0、空字符串三者不同。

### 常见错误
错误：WHERE value = NULL

修正：WHERE value IS NULL

### 注意事项
NULL 的三值逻辑在第5章展开。

## kp15-01 OVER 与 PARTITION BY

### 概念
普通聚合压缩行数；窗口聚合为每行计算所处窗口的指标。

### 语法
```sql
SUM(v) OVER (PARTITION BY key)
```

### 参数说明
- `key`：分区字段
- `v`：指标字段

### 原始数据

**orders**

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### MySQL 示例
```sql
SELECT id,category,sales,SUM(sales) OVER(PARTITION BY category) AS category_total FROM orders ORDER BY id;
```

### 执行过程
1. 按类别建立窗口
2. 各窗口计算总额
3. 把总额写回每一行

### 执行结果
| id | category | sales | category_total |
| --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1400 |
| 2 | 化妆品 | 400 | 700 |
| 3 | 护肤品 | 600 | 1400 |
| 4 | 化妆品 | 300 | 700 |
| 5 | 日用品 | 1500 | 1500 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
同时查看单笔金额与所属类别合计

### 用法辨析
GROUP BY 每组一行，窗口函数保留每条明细。

### 常见错误
错误：用 GROUP BY category 期待保留全部订单

修正：使用 SUM(sales) OVER(PARTITION BY category)

### 注意事项
窗口在行筛选及分组之后计算，不能在同层 WHERE 引用窗口值。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp15-02 ROW_NUMBER、RANK、DENSE_RANK

### 概念
ROW_NUMBER 给每行唯一序号；RANK 同值同名次并留空档；DENSE_RANK 同值同名次不留空档。

### 语法
```sql
RANK() OVER(ORDER BY value DESC)
```

### 参数说明
- `ORDER BY`：窗口内部排名顺序

### 原始数据

**employees**

| employee_id | employee_name | manager_id | salary |
| --- | --- | --- | --- |
| 1 | A | NULL | 8000 |
| 2 | B | 1 | 5000 |
| 3 | C | 1 | 5000 |
| 4 | D | 2 | 3000 |

### MySQL 示例
```sql
SELECT employee_id,salary,ROW_NUMBER() OVER(ORDER BY salary DESC,employee_id) AS rn,RANK() OVER(ORDER BY salary DESC) AS rnk,DENSE_RANK() OVER(ORDER BY salary DESC) AS dense_rnk FROM employees ORDER BY rn;
```

### 执行过程
1. 8000排名1
2. 两个5000并列2
3. 3000的普通排名4、密集排名3

### 执行结果
| employee_id | salary | rn | rnk | dense_rnk |
| --- | --- | --- | --- | --- |
| 1 | 8000 | 1 | 1 | 1 |
| 2 | 5000 | 2 | 2 | 2 |
| 3 | 5000 | 3 | 2 | 2 |
| 4 | 3000 | 4 | 4 | 3 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
按薪资排名并比较并列规则

### 用法辨析
唯一序号加编号消除并列不确定性；RANK 不应随意加唯一键破坏并列。

### 常见错误
错误：WHERE RANK() OVER(ORDER BY salary DESC)<=3

修正：先在 CTE 计算排名，再在外层 WHERE 筛选

### 注意事项
窗口排序并不保证最终输出排序。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0196、q0206、q0207、q0216、q0217、q0218、q0219

## kp15-03 LAG 与 LEAD

### 概念
LAG 获取分区中前一行，LEAD 获取后一行；可指定偏移和缺失默认值。

### 语法
```sql
LAG(v,1) OVER(ORDER BY month)
```

### 参数说明
- `1`：向前偏移一行
- `month`：时间顺序

### 原始数据

**monthly**

| month | sales |
| --- | --- |
| 2026-01 | 1000 |
| 2026-02 | 1500 |
| 2026-03 | 1500 |
| 2026-04 | 900 |

### MySQL 示例
```sql
SELECT month,sales,LAG(sales) OVER(ORDER BY month) AS previous_sales,LEAD(sales) OVER(ORDER BY month) AS next_sales FROM monthly ORDER BY month;
```

### 执行过程
1. 月份排序
2. 每行读取相邻行指标
3. 边界返回NULL

### 执行结果
| month | sales | previous_sales | next_sales |
| --- | --- | --- | --- |
| 2026-01 | 1000 | NULL | 1500 |
| 2026-02 | 1500 | 1000 | 1500 |
| 2026-03 | 1500 | 1500 | 900 |
| 2026-04 | 900 | 1500 | NULL |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
分析月度变化

### 用法辨析
前一行不一定代表上一个自然月，需先补齐月份。

### 常见错误
错误：用 LAG 获取上月但数据有月份缺失

修正：建立连续月份序列后连接并计算

### 注意事项
LAG/LEAD 按排序后的行偏移，不保证恰好是上月或下月；日期缺档需先补齐时间轴。并列排序键应增加稳定决胜键。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0197、q0198、q0202、q0209

关联闪卡：fc0113、fc0120

## kp15-04 ROWS、RANGE 与累计

### 概念
ROWS 按物理窗口行数界定范围；RANGE 按排序值与同值组界定。显式指定累计帧可避免默认帧歧义。

### 语法
```sql
SUM(v) OVER(ORDER BY key ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
```

### 参数说明
- `UNBOUNDED PRECEDING`：从分区起始行
- `CURRENT ROW`：截至当前行

### 原始数据

**monthly**

| month | sales |
| --- | --- |
| 2026-01 | 1000 |
| 2026-02 | 1500 |
| 2026-03 | 1500 |
| 2026-04 | 900 |

### MySQL 示例
```sql
SELECT month,sales,SUM(sales) OVER(ORDER BY month ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS cumulative FROM monthly ORDER BY month;
```

### 执行过程
1. 按月份排序
2. 逐行扩大窗口
3. 累计1000、2500、4000、4900

### 执行结果
| month | sales | cumulative |
| --- | --- | --- |
| 2026-01 | 1000 | 1000 |
| 2026-02 | 1500 | 2500 |
| 2026-03 | 1500 | 4000 |
| 2026-04 | 900 | 4900 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
计算年度累计销售额

### 用法辨析
存在同值排序键时 RANGE 可能同时纳入所有同值行。

### 常见错误
错误：省略帧并假设每行累计一定不同

修正：明确 ROWS 并提供稳定排序键

### 注意事项
不同分区应添加 PARTITION BY，例如按年份重置累计。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0205、q0208、q0210、q0211

## kp15-05 移动平均与环比

### 概念
本例移动平均采用最近三行（含当前行），不足三行取现有行；仅在连续月份数据中才能解释为三个月移动平均。环比仅在上一行确为上月时成立，分母不得为零。

### 语法
```sql
AVG(v) OVER(ORDER BY key ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
```

### 参数说明
- `2 PRECEDING`：向前两行
- `CURRENT ROW`：当前行

### 原始数据

**monthly**

| month | sales |
| --- | --- |
| 2026-01 | 1000 |
| 2026-02 | 1500 |
| 2026-03 | 1500 |
| 2026-04 | 900 |

### MySQL 示例
```sql
WITH m AS (SELECT month,sales,LAG(sales) OVER(ORDER BY month) AS prev,AVG(sales) OVER(ORDER BY month ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS moving_avg FROM monthly) SELECT month,ROUND(moving_avg,2) AS avg3,ROUND(100.0*(sales-prev)/NULLIF(prev,0),2) AS growth_pct FROM m ORDER BY month;
```

### 执行过程
1. 按月计算前三行窗口均值
2. 取上期销售
3. 计算环比百分数

### 执行结果
| month | avg3 | growth_pct |
| --- | --- | --- |
| 2026-01 | 1000.0 | NULL |
| 2026-02 | 1250.0 | 50.0 |
| 2026-03 | 1333.33 | 0.0 |
| 2026-04 | 1300.0 | -40.0 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
分析销售走势并减少波动

### 用法辨析
移动平均是窗口内均值，环比是变化比率。

### 常见错误
错误：直接用当前销售额作环比分母

修正：(当前值-上期值)/NULLIF(上期值,0)

### 注意事项
窗口不足3行时本例按现有行计算；完整3月口径需检查窗口计数。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0203、q0214、q0215、q0220

关联闪卡：fc0111、fc0118

## kp15-06 RANGE 与 ROWS 的并列效应

### 概念
排序键相同的行属于同值组；RANGE 截至当前排序值，可能同时纳入并列行；ROWS 截至具体物理行。

### 语法
```sql
SUM(v) OVER(ORDER BY v RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
```

### 参数说明
- `RANGE`：按排序值范围确定窗口
- `ROWS`：按窗口中的行确定范围

### 原始数据

**employees**

| employee_id | employee_name | manager_id | salary |
| --- | --- | --- | --- |
| 1 | A | NULL | 8000 |
| 2 | B | 1 | 5000 |
| 3 | C | 1 | 5000 |
| 4 | D | 2 | 3000 |

### MySQL 示例
```sql
SELECT employee_id,salary,SUM(salary) OVER(ORDER BY salary RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS range_sum,SUM(salary) OVER(ORDER BY salary,employee_id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS row_sum FROM employees ORDER BY salary,employee_id;
```

### 执行过程
1. 最低薪资3000累计3000
2. 两个5000在 RANGE 中同时计入得到13000
3. ROWS 依次得到8000及13000
4. 8000后合计21000

### 执行结果
| employee_id | salary | range_sum | row_sum |
| --- | --- | --- | --- |
| 4 | 3000 | 3000 | 3000 |
| 2 | 5000 | 13000 | 8000 |
| 3 | 5000 | 13000 | 13000 |
| 1 | 8000 | 21000 | 21000 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
避免按金额累计时因并列出现意外跳变

### 用法辨析
ROWS 使用确定性次排序键；RANGE 的并列语义不应通过随意加入唯一键消除。

### 常见错误
错误：两种窗口帧混用并假设一定相同

修正：先定义业务需要的累计粒度再选窗口帧

### 注意事项
当排序键唯一时，本示例两种累计等价。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0212、q0213

关联闪卡：fc0117

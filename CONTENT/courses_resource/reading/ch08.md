## kp08-01 INNER JOIN 与 ON

### 概念
内连接仅返回满足连接条件的行对；一个父记录匹配多个子记录会产生多行。

### 语法
```sql
FROM a INNER JOIN b ON a.key=b.key
```

### 参数说明
- `ON`：连接谓词
- `a,b`：表或别名

### 原始数据

**orders**

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

**customers**

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

### MySQL 示例
```sql
SELECT o.id, c.customer_name FROM orders o INNER JOIN customers c ON o.customer_id=c.customer_id ORDER BY o.id;
```

### 执行过程
1. 按客户编号配对
2. 无客户的订单不返回
3. 投影编号与名称

### 执行结果
| id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 林 |
| 5 | 王 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
补充订单客户名称

### 用法辨析
JOIN 默认内连接；不是把两张表按行位置拼接。

### 常见错误
错误：JOIN customers c ON o.id=c.customer_id

修正：ON o.customer_id=c.customer_id

### 注意事项
连接前确认主外键和粒度。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp08-02 LEFT JOIN 与 RIGHT JOIN

### 概念
左连接保留左表全部行，右表无匹配时补 NULL；右连接反向保留。

### 语法
```sql
FROM a LEFT JOIN b ON a.key=b.key
```

### 参数说明
- `a`：保留侧
- `b`：匹配侧

### 原始数据

**customers**

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

**orders**

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### MySQL 示例
```sql
SELECT c.customer_id, o.id AS order_id FROM customers c LEFT JOIN orders o ON c.customer_id=o.customer_id ORDER BY c.customer_id,o.id;
```

### 执行过程
1. 客户1匹配两笔
2. 客户2和3各一笔
3. 客户4没有匹配，补NULL

### 执行结果
| customer_id | order_id |
| --- | --- |
| 1 | 1 |
| 1 | 3 |
| 2 | 2 |
| 3 | 5 |
| 4 | NULL |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
列出包括未购买客户的订单关系

### 用法辨析
RIGHT JOIN 可交换两表写成 LEFT JOIN；输出列须明确。

### 常见错误
错误：INNER JOIN 后寻找未下单客户

修正：LEFT JOIN ... WHERE o.id IS NULL

### 注意事项
不要用可空业务字段判断是否匹配；使用非空主键。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0094、q0099、q0101、q0107、q0109

## kp08-03 外连接的 ON 与 WHERE

### 概念
ON 决定匹配，WHERE 在连接完成后筛结果；对右侧字段的 WHERE 条件可能移除补 NULL 的行。

### 语法
```sql
LEFT JOIN b ON a.key=b.key AND b.flag=... 
```

### 参数说明
- `ON`：匹配限制
- `WHERE`：结果过滤

### 原始数据

**customers**

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

**orders**

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### MySQL 示例
```sql
SELECT c.customer_id, COUNT(o.id) AS feb_orders FROM customers c LEFT JOIN orders o ON c.customer_id=o.customer_id AND o.order_date >= '2026-02-01' AND o.order_date < '2026-03-01' GROUP BY c.customer_id ORDER BY c.customer_id;
```

### 执行过程
1. 先限制可匹配的2月订单
2. 保留全部客户
3. 统计非空订单编号

### 执行结果
| customer_id | feb_orders |
| --- | --- |
| 1 | 1 |
| 2 | 0 |
| 3 | 1 |
| 4 | 0 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
统计每个客户的2月订单数，包括零单客户

### 用法辨析
同条件放 WHERE 时，无2月订单的客户可能被删除。

### 常见错误
错误：LEFT JOIN ... WHERE o.order_date >= '2026-02-01'

修正：日期条件放 ON

### 注意事项
COUNT(*) 会把补齐行计为1。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0112、q0113、q0115

关联闪卡：fc0055、fc0061

## kp08-04 CROSS JOIN 与自连接

### 概念
交叉连接形成两表笛卡尔积；自连接使用同一表的不同别名表示不同角色。

### 语法
```sql
FROM employees e LEFT JOIN employees m ON e.manager_id=m.employee_id
```

### 参数说明
- `e`：员工角色
- `m`：主管角色

### 原始数据

**employees**

| employee_id | employee_name | manager_id | salary |
| --- | --- | --- | --- |
| 1 | A | NULL | 8000 |
| 2 | B | 1 | 5000 |
| 3 | C | 1 | 5000 |
| 4 | D | 2 | 3000 |

### MySQL 示例
```sql
SELECT e.employee_name, m.employee_name AS manager FROM employees e LEFT JOIN employees m ON e.manager_id=m.employee_id ORDER BY e.employee_id;
```

### 执行过程
1. 为员工表创建两个逻辑角色
2. 匹配主管编号
3. 顶层主管为空

### 执行结果
| employee_name | manager |
| --- | --- |
| A | NULL |
| B | A |
| C | A |
| D | B |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
展示员工汇报关系

### 用法辨析
CROSS JOIN 不需要匹配条件；自连接通常需要角色关联。

### 常见错误
错误：SELECT employee_name FROM employees CROSS JOIN employees

修正：使用不同别名与明确 ON

### 注意事项
若交叉连接两个分别有4行和3行的表，得到12行。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0108、q0110、q0111

## kp08-05 连接膨胀与预聚合

### 概念
订单与两个一对多明细直接相连，会形成明细组合，导致金额重复；先按共同键汇总再连接。

### 语法
```sql
WITH totals AS (...) SELECT ... FROM parent LEFT JOIN totals ...
```

### 参数说明
- `totals`：每个父键唯一的汇总结果

### 原始数据

**customers**

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

**orders**

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### MySQL 示例
```sql
WITH totals AS (SELECT customer_id,SUM(sales) AS total FROM orders WHERE customer_id IS NOT NULL GROUP BY customer_id) SELECT c.customer_id,COALESCE(t.total,0) AS total FROM customers c LEFT JOIN totals t ON c.customer_id=t.customer_id ORDER BY c.customer_id;
```

### 执行过程
1. 按客户聚合订单
2. 确保每客户一个汇总行
3. 连接客户表

### 执行结果
| customer_id | total |
| --- | --- |
| 1 | 1400 |
| 2 | 400 |
| 3 | 1500 |
| 4 | 0 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
在多明细报表中控制粒度

### 用法辨析
DISTINCT 金额会错误合并不同交易的相同金额。

### 常见错误
错误：SUM(DISTINCT sales) 用于修复连接重复

修正：先按正确业务键聚合，检查连接基数

### 注意事项
缺订单是否可视为0须由业务定义。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0095、q0114、q0116、q0117、q0118

## kp08-06 RIGHT JOIN 与 CROSS JOIN 实操

### 概念
右连接保留右侧全部记录；交叉连接产生所有组合。应先判断希望保留哪侧以及目标结果粒度。

### 语法
```sql
FROM a RIGHT JOIN b ON a.id=b.id; FROM a CROSS JOIN b
```

### 参数说明
- `RIGHT JOIN`：右表为保留侧
- `CROSS JOIN`：全部行组合

### 原始数据

**orders**

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

**customers**

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

**stores**

| store_id | store_name |
| --- | --- |
| 1 | 古晋 |
| 2 | 美里 |
| 3 | 诗巫 |

### MySQL 示例
```sql
SELECT c.customer_id,COUNT(o.id) AS matched_orders FROM orders o RIGHT JOIN customers c ON o.customer_id=c.customer_id GROUP BY c.customer_id ORDER BY c.customer_id;
```

### 执行过程
1. 右侧四位客户都保留
2. 客户1匹配2单
3. 客户4无订单，计数0

### 执行结果
| customer_id | matched_orders |
| --- | --- |
| 1 | 2 |
| 2 | 1 |
| 3 | 1 |
| 4 | 0 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
补齐包括未下单客户在内的购买记录

### 用法辨析
把 RIGHT JOIN 的两表互换可改写为 LEFT JOIN；CROSS JOIN 则不按相等条件匹配。

### 常见错误
错误：RIGHT JOIN 后使用 WHERE o.id IS NOT NULL，误删未匹配客户

修正：保留无订单客户时移除该条件，或将业务过滤移入 ON

### 注意事项
交叉连接用于月份与门店等完整维度组合，必须警惕行数相乘。SQLite 3.39及以上支持 RIGHT JOIN。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

## kp08-07 笛卡尔积与完整维度

### 概念
CROSS JOIN 可构建所有维度组合，例如每个月份与每家门店；再左连接真实销售数据可补齐无交易组合。

### 语法
```sql
SELECT ... FROM a CROSS JOIN b
```

### 参数说明
- `a,b`：需要组合的两组维度

### 原始数据

**stores**

| store_id | store_name |
| --- | --- |
| 1 | 古晋 |
| 2 | 美里 |
| 3 | 诗巫 |

**monthly**

| month | sales |
| --- | --- |
| 2026-01 | 1000 |
| 2026-02 | 1500 |
| 2026-03 | 1500 |
| 2026-04 | 900 |

### MySQL 示例
```sql
SELECT s.store_id,m.month FROM stores s CROSS JOIN monthly m ORDER BY s.store_id,m.month;
```

### 执行过程
1. 取3个门店
2. 为每个门店生成4个月份
3. 共12行

### 执行结果
| store_id | month |
| --- | --- |
| 1 | 2026-01 |
| 1 | 2026-02 |
| 1 | 2026-03 |
| 1 | 2026-04 |
| 2 | 2026-01 |
| 2 | 2026-02 |
| 2 | 2026-03 |
| 2 | 2026-04 |
| 3 | 2026-01 |
| 3 | 2026-02 |
| 3 | 2026-03 |
| 3 | 2026-04 |

验证状态：SQLite实际执行；原生 MySQL 未验证。

### 使用场景
生成完整门店月份报表骨架

### 用法辨析
INNER JOIN 根据键匹配；CROSS JOIN 在无条件时生成全部组合。

### 常见错误
错误：在事实表之间无连接键直接 CROSS JOIN

修正：仅在确实需要全部维度组合时使用

### 注意事项
大表交叉连接可能消耗大量内存；手机执行引擎必须限制输出规模。

### 兼容性
直接兼容。仅在本示例数据与语义范围验证；不代表全部 MySQL 语法兼容。

关联题目：q0096、q0100、q0103

关联闪卡：fc0052、fc0058

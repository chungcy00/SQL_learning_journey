# 第十一阶段第四部分：200张完整 SQL 闪卡

## 使用方法
- `flashcards/ch01.json` 至 `ch20.json` 为正式只读内容；`reading/` 为同一批数据生成的可阅读材料。`flashcard_schema.json` 为结构契约。固定卡号 fc0001—fc0200，版本1.0.0。更新内容不得重用卡号表示不同主题。
- 解压至独立目录；最终整合时把 flashcards、fixtures（建议放到独立 flashcard_fixtures 命名空间，保持或重映射 fixturePath）、review_policy.json、关联文件合并到学习资源目录。不要覆盖题库同名 fixtures 或 manifest。课程采用企业升级版20章、题库采用第三部分300题。按 course_links 的知识点 id 追加闪卡关联字段，保留原题库关联。题号逆向索引可用于练习后推荐复习。
- 125张代码卡自带独立微型数据或常量表达式；其正确查询/状态与预先编写的预期行一致。75张概念及辨析卡为文字回忆，不宣称通过SQL执行。业务卡含50项实际任务链接，微型数据不是完整企业查询结果，原七套数据库仍由上一阶段包提供，不重复打包。
- 正面只显示 `front`，不得在翻转前显示 `back`、验证输出或参考解。结果预测卡翻转前不提供执行答案；如提供填空输入，不把闪卡自评变成正式题库自动判题。表格区分 NULL、空字符串、0，金额分与元不可混用；语法卡回答可包含语法骨架而示例代码独立验证。填空给出标准片段，自评接受合理等价写法。
- `review_policy.json` 保留四档映射与七种复习模式，用户评级/算法状态/会话/笔记/收藏单独存储。必须依据锁定版本 FSRS 实际输出计算到期日，不得硬编码间隔，翻转前禁止评级，跳过或暂停不变更调度，回到已评级卡只读，明确撤销后才重新评级，单次原子写入和防重复点击。原规范未定实现版本和目标保持率、每日上限数值，本包不虚构已运行调度器。

## 编号与版本
- 152个知识点均直接关联至少一张闪卡。300道题均至少有一张共享知识点的复习卡；这是主题级关联，不表示每对卡题逐项独立考核。50个BP任务均直接关联，难度按闪卡回忆深度分配，不沿用300题的难度配额。
- `reference/source_index.json` 记录所用课程、题库、业务任务及数据库指纹。六个独立业务库及综合库与正式题库副本一致。综合库旧摘要哈希过期，见 `reference/manifest_correction.json`（原归档未改动）。

## 验证
运行 `python validation/verify_flashcards.py`，仅需 Python 3 和支持本卡窗口/集合运算的 SQLite（实际3.46.1），无需网络和原目录。脚本从最终JSON构建每卡独立内存库。`validation/mysql/` 提供125份原生脚本，仅在全新独立测试数据库执行，尚未在MySQL 8.4原生服务运行。手机端兼容层、显示及FSRS调度仍需集成验收。详见验证报告。
